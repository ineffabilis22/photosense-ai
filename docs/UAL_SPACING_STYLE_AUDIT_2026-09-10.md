# PhotoSense AI 风格审查：UAL 留白与编辑排版转译

日期：2026-09-10  
活动目录：`work/photosense-ai-editorial-monochrome`  
审查范围：首页、开始点评、分析报告、历史记录、登录、注册  
视口：1440 × 1024、760 × 1000、390 × 844

## 1. 审查目标

在不改变“选择点评语境 → 上传照片 → 生成报告 → 保存并回看历史”闭环的前提下，减少无意义线框，用留白、字体、栏宽、对齐和内容顺序重建层级。参考方法来自 UAL 目标页面及其官方 Space、Layout、Typography、Colour 规范；不复制 UAL 品牌。

## 2. 当前优点

1. 首页、点评、报告和历史均以真实照片或主要任务为视觉中心。
2. 全站已经收敛为衬线、无衬线、等宽三种字体角色，标题与正文层级基本稳定。
3. 橙红强调较克制，主操作、活动导航和重点建议可识别。
4. 1440、760、390 px 的文档宽度均无页面级横向溢出；移动端能保持单列阅读。
5. 上传、分析、报告、历史和身份演示结构尚未被视觉修改破坏。

## 3. 主要问题

### P0：边框承担了过多层级职责

- 首页的照片—报告组合、报告内部三行内容、四步流程同时使用外框、横线和竖线；内容已经有明显图像、底色和间距差异，线条属于重复信息。
- 点评页工作台有整块外框、桌面中线、步骤横线、预览内框和元数据顶线；移动端形成明显“框套框”。
- 完整报告有报告外框、目录线、结论卡、评分卡、照片重点卡、诊断卡和章节底线，多层规则线削弱了“结论 → 证据 → 行动”的主次。
- 历史页工具区、统计区和记录卡均有四边框；评分又使用橙色方框，形成第二套视觉系统。

影响：页面被切成大量同权重矩形，用户先看到框而不是照片、判断和行动。

### P0：选中状态方向错误

- 点评页介质、水平和题材当前项使用左侧橙线。
- 桌面报告目录当前项也使用左侧橙色内阴影；移动端才变为底部线，跨视口逻辑不一致。
- 历史管理项同样存在左侧强调模式。

影响：选中态像警告或引用，而不是标签页/选项；与顶部导航的底部活动线冲突。

### P1：普通中文元数据误用等宽字体

- 点评页整行 `.frame-metadata` 被设为等宽字体，因此“尚未选择文件”“数码摄影”“爱好者水平”“街头摄影”与主体无衬线字体脱节。
- 报告照片属性条也把中文类别与文件参数放在同一个等宽角色中。

影响：中文字形和字面宽度不稳定，呈现“技术占位文本”感。只有日期、评分、编号和真正文件参数应使用等宽。

### P1：内容与边界距离不足

- 用户截图中的照片重点卡和评价基准卡，标题、正文与 1 px 边界之间的空间不足；四边框强化了拥挤感。
- 报告卡内部用 16–24 px 解决所有层级，缺少 40、48、64 px 的跨组节奏。
- 移动端点评页连续区块只由线分开，步骤之间没有足够呼吸空间。

影响：信息虽完整，但扫描时难以判断哪些文字属于同一判断，哪些已经进入下一章节。

### P1：评分块过重

- 历史卡把 `77` 放进大面积橙色方块，视觉强度接近主按钮。
- 报告评分本身已经通过字号、雷达图和橙色数字表达，再加四边框卡会重复强调。

影响：评分压过照片标题、结论和查看报告动作，不符合“评分服务于学习反馈”的产品语义。

### P2：报告移动端目录是可滚动的，但截图中后续项目超出可见区

- 文档本身没有横向溢出，但目录项作为横向滚动内容延伸到屏幕外。
- 截图不能证明滚动提示、键盘访问和焦点自动可见是否完善。

影响：这是交互提示风险，不是页面级溢出；本轮保留滚动结构，只统一选中底线并确保可聚焦。

## 4. 页面修改映射

| 页面 | 删除 | 保留 | 以什么建立层级 |
| --- | --- | --- | --- |
| 首页 | 照片—报告外框、报告内部横线、流程外框与竖线 | 胶片穿孔、主按钮边界、眼睛按钮 | 64 px 章节间距、照片比例、标题与编号 |
| 开始点评 | 工作台外框、中线、步骤横线、元数据顶线、选中项左线 | 输入框、上传按钮、上传区域必要边界 | 两栏空隙、步骤间 40–48 px、底部选中线 |
| 分析报告 | 报告外框、章节底线、结论/评分/诊断/评价基准四边框 | 来源提示单侧线、数据表必要线、导出按钮 | 40–64 px 章节节奏、32–48 px 栏距、标题与编号 |

## 5. 实施步骤

### 步骤 1：基础 Token 与字体

- 补充 40、80、96 px 间距 Token。
- 正文改为 16–18 px 流动字号，保持 1.65 行高。
- 将普通中文元数据统一为无衬线；等宽只保留数字、日期、编号和技术参数。

验证：页面不出现第四种字体角色；“尚未选择文件”“数码摄影”等计算字体为 `--em-sans`。

### 步骤 2：统一活动态

- 删除选项和报告目录的左侧橙线。
- 桌面、平板和移动端统一使用底部 3 px 橙线。

验证：介质、评价水平、摄影题材、报告目录与顶部导航方向一致；语义选中状态保留。

### 步骤 3：首页和点评页去框

- 删除首页照片—报告组合与流程的重复边线。
- 删除点评工作台外框、中线、步骤横线和元数据顶线。
- 用 32–64 px 间距建立组合关系，保留操作控件边界。

验证：照片、报告、步骤仍可辨认；上传、重置和开始分析状态不变。

### 步骤 4：报告去框与重排

- 删除报告壳、章节、结论卡、评分卡、照片重点卡、诊断卡和评价基准的普通边框。
- 保留来源提示和错误/警告的单侧语义线。
- 后期与拍摄行动使用编号、栏距和留白，不使用色块卡片墙。

验证：目录 01–05 和全部内容保持；“结论 → 证据 → 行动”更加清楚；导出样式不受影响。

### 步骤 5：历史与身份页面去框

- 历史工具区和记录条目取消普通外框；评分取消橙色方框。
- 登录/注册外层面板取消装饰框，字段和按钮边界继续保留。

验证：搜索、筛选、管理、对比、查看和删除行为不变；评分仍明显但不抢占主操作。

### 步骤 6：自动化与视觉验收

- 更新样式约束测试，禁止普通内容卡边框和左侧活动线。
- 运行 `npm.cmd run check`。
- 重新截图并检查 1440、760、390 px 的首页、点评、完整报告、历史、登录和注册。

## 6. 可访问性风险与证据边界

- 截图确认了视觉层级、框线密度、文字拥挤和响应式重排，不能单独证明 WCAG 合规。
- 本轮必须另外检查键盘焦点、选中语义、44 px 触控目标、文字对比度和减少动态偏好。
- UAL 目标页面的可读内容结构与官方设计系统可访问；独立无登录浏览器截图被站点反自动化页面阻断，因此具体 4–96 px、12 栏、字体行高等依据来自 UAL 官方设计系统，不把无法核实的页面像素值写成事实。
