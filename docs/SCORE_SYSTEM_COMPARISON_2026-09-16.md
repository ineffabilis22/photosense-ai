## 3. 现有机制的具体不足

1. 模型只选六个 `scoreBands`，服务端再把档位映射为固定分数。即使模型观察到 71 和 78 的差异，最终也会被压成同一个 75。
2. 五维没有可核查的子项。`scoreReasons` 是文字说明，但不参与计算，分数和理由之间缺少结构化约束。
3. 旧 prompt 明确规定两档水平只改变语言，不改变基础视觉分；因此“进阶更严格”没有真正进入评分。
4. 最低分和改进优先级建立在固定档位上，容易出现多张照片都被判断为“可选优化”或都得到相同优先级。
5. 403、连接超时等中转站故障是独立问题。重试只能提高可用性，不能弥补评分规则本身的区分度。

## 4. v4-rubric 评分规则

每个维度由 4 项基础能力和 1 项精修能力组成。每个子项为 0–5 分：

- 0：缺失或失败
- 1：明显不足
- 2：有限可用
- 3：基本成立
- 4：控制稳定
- 5：非常出色

五个维度及子项为：

| 维度 | 四项基础能力 | 精修项的判断重点 |
| --- | --- | --- |
| 构图 | 主体层级、位置与平衡、边缘控制、空间/线条关系 | 是否主动控制边缘、秩序、留白和观看路径 |
| 光线 | 曝光与明暗层次、光线方向/质量/时机、主体分离、高光/阴影控制 | 是否主动塑造层次并让光线服务主体 |
| 色彩 | 和谐与整体调性、色彩层次与主体分离、色彩意图、统一/准确/克制 | 是否有明确色彩意图且处理不过度 |
| 叙事 | 主体/动作/事件清晰度、主体与环境关系、瞬间/情绪/现场张力、具体性 | 是否形成具体、可复述且有选择的表达 |
| 技术完成度 | 对焦/清晰度/细节、曝光完整度、透视/倾斜/后期、介质质感 | 是否在不破坏表达的前提下完成控制 |

计算方式：

- 爱好者水平：`四项基础平均分 × 20`。精修项必须填写，用于给出练习方向，但不因尚未精修而额外扣分。
- 进阶水平：`(四项基础平均分 × 0.8 + 精修项 × 0.2) × 20`。精修项低于基础平均时，会真实拉低对应维度；如果创作意图和控制都很明确，也可以拉高分数。
- 五维总分是五项维度分数的平均值；当前界面仍以五维分数和最低维度作为报告重点。
- 分档只由计算后的 0–100 分生成：作品级 90–100，强 80–89，成立 70–79，普通 60–69，偏弱 45–59，严重问题 0–44。

实现上的保护：

- 新 API 优先使用 `scoreBreakdown`，服务端计算 `scores` 和 `scoreBands`，不接受模型直接覆盖最终分数。
- 子项缺失或越界时只回退对应维度；旧 provider 只有 `scoreBands` 时仍可正常生成兼容报告。
- 同一照片、介质和题材的结构化视觉证据在两档水平间复用，避免因为第二次调用随机漂移；只重新应用不同的严格度公式。
- 报告版本为 `v4-rubric`；旧 v2/v3 历史记录保留，不会被伪装成新规则。

在新代码和新 prompt 生效后，photo-20（巷口微光）通过同一后端完成两次测试：

| 水平 | 构图 | 光线 | 色彩 | 叙事 | 技术完成度 | 说明 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 进阶水平 | 82 | 77 | 77 | 66 | 80 | 巷道空间和光线成立，但没有人物/事件承接亮处，叙事最低。 |
| 爱好者水平 | 84 | 78 | 79 | 68 | 81 | 同一证据下基础能力得分略高，精修不足转化为建议。 |

这两次均返回 `scoreVersion: v4-rubric` 和完整五维 `scoreBreakdown`。分数不再是固定档位代表值，叙事 66 与光线 77 的差异也能从结构化子项追溯。

## 6. 当前限制

- 17 张照片的人工分数是单人直接评估，适合做产品回归基准，不足以证明评分与专业评审或用户学习效果之间的统计一致性。后续若要把它当作正式评测集，应至少加入第二位独立评审并记录分歧。
- 旧 API 基线后 12 张被中转站 403 拦截，因此不能声称完成了 17 张旧 API 的成功对比；失败记录已保留为外部服务可用性证据。
- 新评分仍依赖视觉模型对 0–5 子项的判断。它解决了离散查表和水平不分的问题，但不等于自动消除了模型偏差；后续应使用固定样本回归和人工复核继续校准。
